# Python and Bindings

## Style

- PEP 8 via **ruff** (lint + format, settings in `pyproject.toml`); **pyright** and **ty** for type checking.
- Type hints on every public function and method; modern syntax (`list[str]`, `X | None`).
- Imports: standard library → third party → local, separated by blank lines.
- Raise specific exceptions; chain with `from` when re-wrapping.

## Environment

```bash
uv venv --system-site-packages   # always; matches the devcontainer and CI
uv sync --no-install-project     # dependencies only, no wheel build
```

- Runtime dependencies go in `[project.dependencies]`; build and test tooling (`nanobind`, `pytest`, `ruff`, `pyright`, `ty`) in the `dev` dependency group. Add with `uv add <pkg>` / `uv add --dev <pkg>` and commit `uv.lock`.
- If your uv is configured with a mirror index, lock with `UV_DEFAULT_INDEX=https://pypi.org/simple uv lock` so `uv.lock` keeps pypi.org URLs.

## Package layout

- `src/basjoo/` holds both the C++ sources and the Python package (`__init__.py`, pure-Python modules, the nanobind `_core` extension). xmake-python only accepts `<name>/` or `src/<name>/` layouts, which is why they share a directory.
- `_core.pyi` and `py.typed` are generated by `nanobind.stubgen` during the build — never edit them by hand.
- CMake/xmake build `_core` into `src/basjoo/` against `.venv/bin/python`, so run the environment setup first.

## Build backends

- `pyproject.toml` is a **symlink** to `pyproject.cmake.toml` (scikit-build-core driving the CMake presets). `pyproject.xmake.toml` is the xmake-python alternative: switch with `ln -sf pyproject.xmake.toml pyproject.toml` — never `cp`, which writes through the symlink and overwrites `pyproject.cmake.toml`.
- The two files share `[project]`, `[dependency-groups]`, and `[tool.*]` sections, kept identical by hand.
- xmake-python always runs a bare `xmake` build, so it builds every default-enabled target, not just `_core`.

## Sanitizers

`_core` and nanobind are always compiled with `-fno-sanitize=address,undefined` on GCC/Clang (CMake `target_compile_options`, xmake `on_config` with `{force = true}`), so importing the extension never needs a preloaded sanitizer runtime in any build type. Everything else keeps ASan/UBSan.
